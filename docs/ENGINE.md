# «Новобранець» — прототип двигуна

Двигун забігу без UI. Мета — перевірити головну гіпотезу ТЗ: **чи цікаво грати, коли фінал відомий наперед**.

## Запуск

```bash
npm test        # 10 тестів: детермінізм, фінали, межі показників, директор
npm run sim     # 8000 забігів у 4 стилях гри → розподіл днів, рішень, фіналів
node --experimental-strip-types scripts/validate.ts   # перевірка контенту
```

Node 25, без залежностей.

## Що всередині

```
src/types.ts        типи: показники, навички, картки, фінали, конфіг директора
src/rng.ts          детермінований PRNG (mulberry32) — забіг відтворюється за seed
src/conditions.ts   умови (AND-блоки) і застосування ефектів з затисканням 0..10
src/run.ts          ядро: draw/choose, фази, «директор долі», вибір фіналу
src/validate.ts     валідатор контенту (дублі, мертві прапорці, порожні фази)
data/test-content.ts 32 картки, 8 фіналів у тоні ТЗ
scripts/simulate.ts  баланс-симулятор
test/run.test.ts     автотести
```

## Ключові рішення, вшиті в код

| Рішення | Чому |
|---|---|
| Детермінований seed | забіг можна відтворити, баг відтворюється, аналітика чесна |
| Смерть від «долі» окремо від смерті від здоров'я=0 | перше — система, друге — явна помилка гравця; ТЗ вимагає цієї різниці |
| Жорсткий тригер на день **60**, а не 90 | 90 днів у фазі 5 = провал темпу (зауваження №1 до ТЗ) |
| Зростання шансу смерті після дня 30 | «лічильник неминучості» з ТЗ, але з плавним рампом, а не обривом |
| Голод/виснаження підвищують шанс (до ×1.85) | бідність вибору має ціну, але обізнаність — ні |
| Показники 0..10, навички 0..3 | як у ТЗ |
| Мертвий прапорець = помилка валідації | умова, яку ніхто не встановлює, — це мертвий контент |

## Симуляція: перші результати

2000 забігів на стиль. Контент — 32 картки, тому цифри показують **механіку**, а не фінальний баланс.

| Стиль гри | Днів (медіана) | Рішень | Різних фіналів |
|---|---|---|---|
| «обізнаний» (Розуміння+Зв'язки) | 29 | 71 | 3 |
| «виживальник» (Здоров'я+Запаси) | 31 | 73 | 3 |
| «конформіст» (Довіра) | 11 | 29 | 3 |
| випадковий | 14 | 39 | 4 |

**Що це вже показує:**

1. **Конформізм карається.** Гравець, який догоджає системі, живе вдвічі менше — 11 днів проти 29. Це найсильніше повідомлення гри, і воно виходить з механіки, а не з тексту. Саме цього домагається ТЗ.
2. **Довжина забігу поки закоротка.** Медіана 29 днів ≈ 70 рішень. ТЗ хоче 15–25 хв → це приблизно 60–120 рішень, тобто межа норми, але p10 = 22 дні. На 32 картках пул швидко вичерпується — треба 80 карток, як у MVP, і м'якший рамп смертності в перші 30 днів.
3. **Фінали одноманітні.** Три фінали з восьми забирають 95%. Причина — умови фіналів жорсткі (`understanding >= 6, bonds >= 6` майже недосяжно при такій короткій грі). Після балансування роampу фінали треба перевірити ще раз — інакше «≥2 різних фінали на гравця за місяць» не виконати.

## Наступні кроки (порядок має значення)

1. **Розширити контент до 80 карток** і повторити симуляцію — без цього решта балансування марна: пул визначає все.
2. **Підкрутити рамп директора** під цільову тривалість 60–120 рішень (зараз ~70).
3. **Пом'якшити умови рідкісних фіналів** — щоб вони були рідкісні, але досяжні.
4. Тільки після цього — UI. Ядро вже достатньо стабільне, щоб зверху повісити Reigns-подібний свайп.

## Обмеження прототипу (свідомі)

- Немає метапрогресії між забігами (розділ 4.2 ТЗ) — це наступний шар.
- Немає вагової кривої для персонажів (Толік, Оля, командир) — картки роздаються плоско.
- Карток 32, а не 80; фіналів 8, а не 6 — навмисно більше, щоб перевірити, чи вони розрізняються.
- Локалізації немає: тексти одразу українською, але структура (окремі рядки в картці) готова до `ua/en` словників без переписування логіки.
